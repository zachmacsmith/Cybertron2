# Thread tracking: a registry, hooks, checks and a commit schema

*proposal · accepted: D2-235 (20 Nov); built as W-65 · `docs/cybertron2/proposals/thread_tracking.md`*

> a registry of threads WORK.md is rendered from, a session-start brief and a stop check as hooks, checks on push, a weekly status page, and commit trailers naming the agent, the threads and the ids opened and closed


**Status:** accepted: [[D2-235 Commits typed and labelled|D2-235]] (and [[D2-232 The records as items|D2-232]] to [[D2-234 Documents in the web|D2-234]]) (20 Nov).

**Owner:** 37.2 (process tooling; WORK [[W-65 The records system|W-65]]).

## Summary

Work goes missing in the records because nothing checks them against the work itself (02zzp). This proposal adds four mechanisms,
which Zach asked to have built, and a commit schema, which he asked about on 20 Nov:
- a registry of threads that WORK.md is generated from;
- a brief at session start and after each compaction, and a stop check that blocks a reply whose commitments have no row;
- checks of the records against the repository on every push to main;
- a status page refreshed weekly;
- **commit trailers**, so every commit names its agent and its threads, and every id it opens or closes. The checks hold these
  claims against the diff.

## The proposal

### Built ([[W-65 The records system|W-65]])

1. **The registry** (`docs/cybertron2/threads.json`, `tools/threads.py`). It holds each W row's cells together with what a table
   cell cannot hold: the branches, the asks the row waits on, the next step. It also holds the offers and promises (O-n, each with
   a default and a date for it). WORK.md is rendered from the registry. A hand edit to WORK.md wins: `sync` takes in every row that
   differs from its last rendering before anything is written. The registry is JSON so the hooks need only the standard library,
   as hygiene.py does.
2. **Hooks** in the repository's `.claude/settings.json`, so every session runs them:
   - SessionStart (startup, resume, compact): `threads.py brief`, which prints the live threads by owner, offers past their
     default, branches ahead of main that no row names, and old asks;
   - Stop: `threads.py stopcheck`, which blocks a reply that makes a commitment ("next I'll", "shall I", "left:", "owed") when no
     tracking file changed in that turn.
3. **Checks on push to main** (a GitHub Action running `threads.py check` and hygiene). It fails only on hard errors: duplicate
   live ids, or a WORK.md out of step with the registry.
4. **A status page** generated by `threads.py page`, published as a private page and refreshed weekly.

### The commit schema (proposed, not built)

**Trailers.** A commit ends with trailers, which git can parse (`git log --format='%(trailers:key=Thread)'`). Git reads trailers
only from the last paragraph, so they go in one block with the attribution lines and no blank line between (found on 8825a36,
whose trailers git does not see):

```
WORK [[W-65 The records system|W-65]]: the registry and WORK.md rendered from it

<body>

Agent: 37.2
Thread: [[W-65 The records system|W-65]]
Opens: [[O-1 A first wiki generated from the spec as it stands, as a private page…|O-1]], [[Q-63 A commit schema|Q-63]]
Closes: [[W-63 The audit of work started and left, and the triage of open asks and…|W-63]]
Decides: [[D2-232 The records as items|D2-232]]
Co-Authored-By: ...
Claude-Session: ...
```

| Trailer | Required | Holds | Checked against the diff |
|---|---|---|---|
| `Agent:` | yes | the session's role (37.2, 37.4, c2viz, lead) from a fixed list | the name is on the list |
| `Thread:` | yes, one or more | the W rows the commit works on; `upkeep` for a chore that belongs to no thread | each W id is live, or moves to Done in this commit |
| `Opens:` | when it adds ids | every W, Q, L, O or D id first written in this commit | each id's row is added in the diff, and is not already on main |
| `Closes:` | when it ends one | W rows moved to Done; Q, L or O rows closed or struck | the row moves or is struck in the diff |
| `Decides:` | when DECISIONS gains a row | the D ids | the row is added to DECISIONS.md, citing Zach's own words |

**The tree.** Each new Q, L and O row names its parent thread in a cell (`thread: [[W-65 The records system|W-65]]`), and the registry keeps the same link. The
outline is derived from these links, with no hand upkeep:
- per thread: its commits, the files they changed, the ids they opened and closed, its last touch, its branches;
- per id: the thread it belongs to and the commit that opened it.

Proposals keep their filenames as their ids.

**What becomes automatic.** A row's "last touched" is its latest commit, and "where" includes the files its commits changed. A
commit on a branch that names a thread shows that the branch holds that thread's work. A commit with no thread is reported. These
are the gaps 02zzp found by hand.

**Enforcement:**
- **At commit**, for agents: a PreToolUse hook on `git commit` reads the message and refuses a commit with no `Agent:` or
  `Thread:` trailer, or with an id that is not on main or in the diff.
- **On push**, for everyone: the Action checks every new commit's trailers against its diff and reports what fails in the run's
  summary. The next session's brief shows it too. A direct push to main cannot be refused this way, so Zach's own hand commits only
  draw a warning.

**The ids.** Keep the flat series (W-n, Q-n, L-n, O-n; D2-n and D4-n by session). Do not nest them under threads:
- an ask often belongs to two threads ([[Q-60 The water worlds' people, and the runs world for the…|Q-60]] serves [[W-58 The runs world with a model to each household|W-58]] and [[W-59 The runs world for the model-per-household run|W-59]]);
- an ask often outlives its thread ([[L-117 Wildlife pack K3 forays, methods and knowing|L-117]] to [[L-127 The ecology's calibration backlog|L-127]] outlived [[W-6 Merging the wild layer into main|W-6]]);
- a nested id would need renaming each time its thread is merged or split.

The parent link gives the tree without these faults.

**Collisions.** The shared W series has already collided seven times: [[W-28 The Cybertron 2 website|W-28]], [[W-34 Worlds for the peoples benchmark|W-34]], [[W-38 Generation redesign|W-38]] and [[W-39 The economy's web of dependence and how far it should reach|W-39]] are each used twice, and [[W-49 Environment systems|W-49]], [[W-52 The lake world's second live run|W-52]]
and [[W-57 The lake runs' seven engine faults|W-57]] had to be renumbered. They happen when two sessions take a number before either has pushed. The fix: `threads.py next Q`
gives the next number after a fetch, the commit hook refuses an id already on main, and the push check refuses a duplicate. The
second session to push then renumbers during its rebase.

## Why

Zach (20 Nov): "Can we make a commit schema, so commit messages have to label which agent makes the commit and which thread they
are currently contributing to / which threads they complete in some way? Then we can have a direct commit to documentation
outline? And especially if we have a consistent ID formattign for any new opened questions, proposals etc, each as a sub of the
current threads etc.?"

The registry depends on agents keeping it up to date. Commits are made anyway, and they are the one record that cannot fall
behind the code. Labelled commits let the registry's dates and places be read from git, and let a check compare what a commit
claims (opened, closed) with what its diff did.

## Alternatives considered

- **Ids nested under threads** ([[W-65 The records system|W-65]].Q1). Rejected for the reasons under "The ids".
- **Series by session for all kinds** (W2-n, Q4-n, as the decisions already are). This would end collisions outright, at the cost
  of two id formats in the documents for good. Worth taking only if collisions go on after the push check.
- **Free-form subjects only** (today's habit: 141 of the last 400 subjects name a W row). These are readable, but they cannot be
  checked: nothing tells a thread named from one only mentioned, and closes are never stated.
- **A git commit-msg hook.** It lives in `.git/hooks`, which a clone does not carry, so new sessions would lack it. A Claude Code
  hook in the committed settings reaches every agent session.
