# Branches (D2-238)

*live · 20 Nov · spec: [[process - how_we_work|process/how_we_work]]*

## The rule
[no spec]: merge to main early, but not to an extreme: a branch is fine for a distinct thread or for exploring; branches are revisited periodically; runs go from main, unless a run with a distinct purpose needs its own branch, which is labelled as a run thread, and there should be few of those; no empty or stale branches left to clutter

## Where it came from
proposals/records_and_workflow.md §5; conversation (20 Nov, ask 6: "I think mostly but not too extreme. Work living on other branches is fine if it is actually a different thread or something being explored. But I do think periodically revisiting branches is important as well and runs should go from main unless I have distinct things running for a purpose but the branches should be labelled in some way as distinct 'run' threads ... We should also not want a bunch of random empty branches")

## What it replaced
merging only at Zach's go, in large merges
